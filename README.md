# المواجهة | AL MWAJHA

لعبة مواجهة كروية (مزاد لاعبين، تاخد اللاعب ولا الخفي، ديل أور نو ديل، اقف ف صفي عشان بصفي، وألعاب تانية) — React + TypeScript +
Vite على الواجهة، وSupabase (Postgres) كقاعدة بيانات وسيرفر منطق لعب. الملف ده هو التوثيق الأساسي للمشروع،
وتفاصيل آخر تحديث للألعاب موجودة في `PATCH_NOTES_AR.md`.

---

## 1) تشغيل المشروع محلياً

**المتطلبات:** Node.js 20+

```bash
npm install
npm run dev        # يفتح على http://localhost:3000
```

أوامر تانية مفيدة:

```bash
npm run build              # بناء نسخة الإنتاج في dist/
npm run lint                # فحص TypeScript فقط (tsc --noEmit) — لازم يطلع نضيف من غير أخطاء
npx tsx tests/safiEngine.test.ts               # اختبار لعبة اقف ف صفي
npx tsx tests/matchEngine.goalkeeper.test.ts   # اختبار قواعد الحارس في المحاكاة
npm run android:sync        # بناء + مزامنة مع مشروع Android (Capacitor)
npm run android:open        # فتح مشروع Android في Android Studio
```

## 2) إعداد Supabase (خطوة إجبارية للألعاب الأونلاين)

كل منطق اللعب الحساس (الفلوس، المزايدات، الأدوار، الأسرار، الغرف) لازم يشتغل على السيرفر، مش على المتصفح.
الملف الوحيد اللي يحتوي على قاعدة البيانات بالكامل هو:

```
supabase/SUPABASE_SETUP.sql
```

**خطوات التركيب (مرة واحدة، وآمن تعيده أي وقت):**

1. افتح مشروعك على [supabase.com](https://supabase.com) → **SQL Editor** → **New query**.
2. الصق محتوى `supabase/SUPABASE_SETUP.sql` كامل واضغط **Run**.
3. من **Authentication → Providers** فعّل **Allow anonymous sign-ins** (كل لاعب بياخد هوية سرية من غير إيميل/باسورد، والسيرفر بيعتمد عليها في كل حاجة).
4. اعمل يوزر أدمن من **Authentication → Users → Add user** (إيميل + باسورد)، وبعدين شغّل في SQL Editor:
   ```sql
   insert into public.admin_users (email) values ('you@example.com') on conflict do nothing;
   ```
5. اعمل ملف `.env` في جذر المشروع:
   ```
   VITE_SUPABASE_URL=https://xxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

الملف اتبنى واتختبر فعلياً (تحميل كامل على PostgreSQL 16 من غير أي خطأ، واختبارات فعلية للمزايدة والمراكز
وسرية الصناديق — تفاصيل القسم 5).

## 3) بنية المشروع

```
src/
  components/     شاشات الواجهة (كل لعبة، الغرف، البروفايل، البطولات...)
  admin/          لوحة تحكم الأدمن (رفع صور اللاعبين، إدارة الألعاب)
  services/       منطق العميل: تخزين محلي، محركات الألعاب الحالية، Supabase client
  types/          كل الـ TypeScript interfaces (اللاعب، الغرفة، البطولة، المدرب...)
  data/           بيانات اللاعبين والمدربين والأندية المدمجة (احتياطي/تجريبي)
supabase/
  SUPABASE_SETUP.sql   ملف قاعدة البيانات الكامل الوحيد (شغّله مرة واحدة، آمن يتكرر)
android/          مشروع Capacitor لبناء تطبيق أندرويد من نفس الكود
```

## 4) الحالة الحقيقية للمشروع دلوقتي (بصراحة، من غير مبالغة)

### شغال ومتزامن حقيقي عبر السيرفر (Supabase)
- **الغرف:** إنشاء غرفة عامة/خاصة، انضمام بكود يتحقق منه السيرفر، دعوة صديق، جاهزية، بدء اللعبة.
  الغرف الخاصة عمرها ما تظهر في القائمة العامة مهما حاول حد.
- **محرك المزاد:** الرصيد، المزايدات، منع تجاوز الميزانية، منع التكرار (ضغط متكرر أو طلبات متأخرة)،
  كله بيتحقق منه السيرفر جوه معاملة واحدة بقفل صف (`FOR UPDATE`) — مش الواجهة.
- **محرك تاخد اللاعب أو الخفي:** المراكز بتتحدد بمطابقة صريحة (كل مركز بخانته بالظبط، من غير تكرار حارس
  أو خلط دفاع/وسط)، والمؤقت من السيرفر، والتشكيلة النهائية والمدرب بيظهروا للطرفين مع بعض قبل زر
  "يلا نشوف مين هيكسب".
- **محرك ديل أور نو ديل:** محتوى الصناديق والكروت مخزّن في جدول مقفول تماماً على العميل (`match_secrets`)،
  وبيتكشف بس وقت الفتح الفعلي. فيه دالة `dnd_judge_view` مخصصة للحكم (بشري لو موجود، أو النظام نفسه)
  تكشف كل حاجة، وأي لاعب عادي يحاول ينادي عليها بيترفض فوراً.
- **الذكاء الاصطناعي:** بيقيّم الرصيد، الندرة، سلوك الخصم، ويقدر يخدع أو ينسحب أو يخاطر. كل ماتش بيتحدد
  له "يوم" عشوائي (`ai_skill` بين 0.7 و1.3) فمفيش نتيجة مضمونة — ممكن يكسب أقوى اللعيبة وممكن يخسر من
  مبتدئ، بالظبط زي لاعب حقيقي.
- **إعادة الاتصال:** الحالة كلها على السيرفر، فلو حد قطع نت ورجع بيلاقي نفس المكان بالظبط، والانقطاع
  الطويل (أكتر من دقيقتين) بيتحسب انسحاب.

### لسه شغال بمنطق المتصفح (مش متزامن حقيقي بين لاعبين بعد)
محركات الألعاب في `src/services/*.ts` (النسخة اللي فعلاً متوصلة بالواجهة دلوقتي) لسه بتشتغل جوه المتصفح
ضد بوت محلي، مش ضد لاعب حقيقي عبر السيرفر. يعني المزاد والغرف اللي شايفها في الواجهة دلوقتي شغالين، بس
مش بيستخدموا محرك الـ Supabase الجديد لسه. الخطوة الجاية المطلوبة هي استبدال `src/services/auctionEngine.ts`
و`src/services/dealOrNoDealEngine.ts` وما شابه بنداءات RPC مباشرة على الدوال اللي في `SUPABASE_SETUP.sql`
(`room_create`, `auction_bid`, `tph_pick_shown`, `dnd_open_box`, إلخ) بدل المحاكاة المحلية.

### أهم الأخطاء اللي اتصلحت قبل كده
- تاخد اللاعب أو الخفي كان بيسحب جولتين حارس مرمى أحياناً بسبب فرق في حساب رقم الجولة — اتصلح على
  مستوى محرك السيرفر بالكامل ومختبر.
- 4 من 5 ألعاب في وضع البطولات كانت بتسجّل "فوز" لأي حد يضغط رجوع حتى لو خسر أو انسحب فعلاً — دلوقتي
  كل لعبة بترجع نتيجتها الحقيقية (فوز/خسارة/تعادل) لمحرك البطولة.
- لعبة "الحوارتجي والصياد" مكنش عندها نهاية حقيقية (تلف لا نهائي) — ضيف ليها حد 5 جولات ونتيجة حقيقية.
- لعبة التخمين كانت بترد "لأ" ثابتة على أسئلة زي "فاز بكأس العالم؟" لإن البيانات دي مش موجودة
  أصلاً — اتشالت الأسئلة دي، واللعبة اتكتبت من جديد بأسئلة جاهزة مبنية على بيانات حقيقية (شوف `PATCH_NOTES_AR.md`).
- إعدادات مزاد البطولات كانت مختلفة عن اللعب العادي (مؤقت 30 ثانية ثابت بدل 5/10/15، وكروت شغالة
  افتراضياً) — اتوحدت مع نفس إعدادات اللعب العادي.
- الشعار كان متكرر 3 مرات في الهيدر والسايدبار والدروار، وكلمة "PRO" ظاهرة جنبه — اتشالوا، وبقى شعار
  واحد بس في الهيدر العلوي.
- اختيار نمط المزاد (100M/200M) كان مستخبي بالكامل بسبب فرق حروف كبيرة/صغيرة في مقارنة الكود.
  دلوقتي الاختيار بيظهر مرة واحدة بس، في شاشة إعداد المزاد بعد اختيار الخصم.
- المشروع كان ناقصه `@types/react` من الأساس، وده كان بيخلي TypeScript يعمي عينه عن 39 خطأ حقيقي —
  اتضافت وكل الأخطاء اتصلحت. `npm run lint` بيطلع صفر أخطاء، و`npm run build` بينجح (فيه تنبيه عادي عن حجم الملف الكبير).
- ملفات كود ميتة (مش متصلة بأي حاجة) اتشالت: `AdminDashboardView`, `InGameChat`, مشاهد خلفية غير
  مستخدمة، `aiAdvisor.ts`, `liveMatchService.ts`. اعتماديات مش مستخدمة اتشالت من `package.json`
  (`@google/genai`, `express`, `dotenv`). مجلد مشروع Flutter/Node قديم غير مرتبط (`el3bha_sa7/`) اتشال.

## 5) اختبارات اتعملت فعلياً على `SUPABASE_SETUP.sql`

اتحمّل الملف على PostgreSQL 16 حقيقي (مش تصور نظري) واتعمله السيناريوهات دي:

| الاختبار | النتيجة |
|---|---|
| مزايدة فوق الرصيد المتبقي (10M ومحاولة 11M) | `INSUFFICIENT_BUDGET` — مرفوضة |
| البوت برصيد 0.3M بس يحاول يزايد بحد أدنى | بيمتنع تلقائياً، زي إنسان بالظبط |
| ضغط متكرر بنفس الطلب (نفس request id) 3 مرات | مزايدة واحدة بس اتسجلت |
| جولة كاملة "تاخد اللاعب" (5 لاعبين) | تشكيلة `[GK, CB1, CM, CM2, ST]` — كل خانة بمركزها الصحيح، من غير تكرار حارس |
| لاعب عادي يحاول ينادي `dnd_judge_view` | `NOT_A_JUDGE` — مرفوض |
| الحكم البشري ينادي `dnd_judge_view` | بيشوف كل الصناديق والكروت لحظياً |
| الخصم يحاول يشوف صناديق التاني قبل الفتح | ميشفش غير `{key, opened}` بس، من غير أي محتوى |

## 6) لوحة الأدمن

من `src/admin/` — الأدمن بيدخل، يختار اللعبة، يرفع لحد 50 صورة دفعة واحدة، يختار المركز من قائمة منسدلة
(حارس، ظهير يمين، ظهير شمال، قلب دفاع 1، قلب دفاع 2، ارتكاز، وسط، وسط ثاني، جناح شمال، جناح يمين، مهاجم،
مدرب)، ويحفظ. الدالة `admin_add_assets` في SQL بترفض أي مركز مش من القائمة دي، وبترفض أكتر من 50 صورة
في الطلب الواحد.

تجريبية/عرض؛ استبدلها ببيانات حقيقية مرخّصة قبل أي إطلاق تجاري.
